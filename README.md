# reg_tracker — 규제·방법론 개정 추적기

온실가스 규제는 고시·지침·별표가 수시로 바뀐다. 이 도구는 국내 고시와 행정예고, EU CBAM 관련 법령을 주기적으로 확인한다. 바뀐 조항을 원문 단위로 비교하고, Claude로 실무 영향을 요약한 뒤, 그 변경이 내 계산 코드의 어느 계수·요건에 닿는지까지 연결한다.

뉴스 요약이 아니라 **원문 비교**가 출발점이다. 요약은 그 위에 얹는다.

## 무엇을 추적하나

| 출처 | 대상 | 방식 |
|---|---|---|
| 국가법령정보센터 | 환경성적표지 작성지침(별표·부속서 포함), 배출권거래제 배출량 보고·인증 지침, 외부사업 타당성 평가·감축량 인증 지침 | 개정 이력을 받아 최신본과 직전본을 조·별표 단위로 비교 |
| 국민참여입법센터 | 제목에 키워드(환경성적표지, 배출권거래제, 온실가스 등)가 든 행정예고 | 새 예고의 본문을 받아 요약 |
| EU 출판국 SPARQL·Cellar | CBAM 규정 (EU) 2023/956을 개정하거나 그에 근거한 법령 | 새로 나온 법령의 본문을 받아 요약 |

추적 대상은 [config/sources.yaml](config/sources.yaml)에서, 영향 연결표는 [config/impact_map.yaml](config/impact_map.yaml)에서 고친다. 별도 API 인증키 없이 공개 페이지만 쓴다.

## 처리 흐름

1. **수집**: 버전 목록과 원문을 받는다. 별표는 PDF에서 텍스트를 뽑는다. 받은 원문은 `.cache/`에 저장해 같은 버전을 다시 받지 않는다.
2. **구조화**: 본문은 조(제N조) 단위로, 부칙은 고시 번호 단위로 나눈다. 별표는 PDF 줄바꿈이 버전마다 달라서, 공백을 없애고 문장·번호 단위로 다시 끊은 뒤 가장 가까운 제목을 위치로 붙인다.
3. **비교**: 단위별로 추가·삭제·수정을 찾고, 숫자만 바뀐 곳(계수·기한)은 따로 짝지어 표시한다. 띄어쓰기와 줄바꿈만 다른 경우는 버린다.
4. **요약**: Claude가 공식 제·개정문(개정이유·주요내용)과 변경 목록을 함께 읽고, 위치별로 무엇이 바뀌었는지와 중요도(높음·보통·낮음)를 적는다. 변경이 많으면(예: 별표 전면 개편) 위치별로 묶어 나눠 보낸다.
5. **영향 연결**: 연결표에서 후보를 코드로 먼저 고르고, 실제 관련 여부와 이유는 Claude가 판정한다. Claude는 후보 밖의 대상을 붙일 수 없다.
   - 고시 개정·EU 법령: 출처 문서가 연결표의 대상과 이어지고, 바뀐 내용에 대상 키워드가 있어야 후보가 된다.
   - 행정예고: 출처 문서가 정해져 있지 않아 본문 키워드만으로는 오탐이 많다. 그래서 제목에 추적 중인 고시 이름이나 대상별 제목 키워드(`notice_titles`)가 먼저 들어 있어야 한다. 예를 들어 "자동차 온실가스 전과정평가 고시"는 본문에 '검증'이 있어도 스크리너의 MRV 요건에 연결되지 않는다.
6. **보고**: `reports/YYYY-MM-DD.html`과 같은 이름의 `.json`을 만든다.

## 다른 저장소에서 읽기

요약까지 마친 실행은 [feed/alerts.json](feed/alerts.json)을 갱신한다. 다른 저장소는 아래 주소에서 자기 저장소 이름이 `targets[].repo`에 들어간 알림만 골라 읽는다.

```
https://raw.githubusercontent.com/cafeon90-oss/reg_tracker/main/feed/alerts.json
```

이미 반영한 알림 id는 각 저장소의 확인 완료 파일(예: `data/reg_ack.json`)로 걸러 낸다. 형식은 [feed/SCHEMA.md](feed/SCHEMA.md)에 있다. 현재 CBAM 계산기가 이 피드를 읽는다.

## 평가

탐지가 맞는지는 실제 과거 개정본 쌍으로 확인한다. 정답은 각 개정의 **공식 제·개정문**에 적힌 변경 위치다. 제·개정문에는 없지만 원문을 직접 대조해 확인한 변경은 오탐으로 세지 않는다. 사례와 근거는 [eval/cases.yaml](eval/cases.yaml)에 있다.

```bash
python eval/run_eval.py          # 변경 탐지만(무료)
python eval/run_eval.py --llm    # 요약의 중요도 판정·핵심어까지(API 비용 발생)
```

최근 결과는 [eval/results.md](eval/results.md)에 남는다.

2026-10-25 기준 결과(사례 3건):

| 사례 | 변경 건수 | 위치 재현율 | 위치 정밀도 | 중요도 판정(기대→결과) |
|---|---:|---:|---:|---|
| 환경성적표지 작성지침 2025-127 → 2025-165 (기관명 변경) | 7 | 1/1 | 3/3 | 낮음 → 낮음 |
| 환경성적표지 작성지침 2024-29 → 2025-127 (별표 4·5 개편) | 299 | 3/3 | 4/4 | 높음 → 높음 |
| 배출량 보고·인증 지침 2025-28 → 2025-64 (제43조 삭제) | 2 | 2/2 | 2/2 | 낮음 → 낮음 |

사례가 3건뿐이라 이 숫자는 출발점일 뿐이다. 개정이 나올 때마다 사례를 늘린다. LLM 평가 1회에는 Claude 호출 7회, 입력 약 10만·출력 약 2만 토큰이 들었다.

## 사용법

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt     # macOS·Linux는 .venv/bin/pip
cp .env.example .env                               # ANTHROPIC_API_KEY 입력
```

```bash
python -m regtracker run                    # 전체 확인 + 보고서 생성
python -m regtracker run --no-llm           # 요약 없이 비교만
python -m regtracker versions kr-epd-guideline
python -m regtracker compare kr-epd-guideline 2024-29 2025-127
python -m pytest
```

이미 보고한 버전·예고·법령은 `data/seen.json`에 기록해 다음 실행에서 다시 보고하지 않는다. 처음 실행하면 고시는 최신 개정 1건을, 행정예고와 EU 법령은 최근 120일 치를 보고한다.

## 알려진 한계

- **별표 비교의 잡음**: PDF 표는 추출 순서가 버전마다 달라질 수 있다. 표 안의 행이 옮겨 가면 실제 값이 같아도 변경으로 잡힐 수 있으며, 이런 항목은 요약 단계에서 "형식 변경"으로 낮게 분류한다.
- **요약에 쓰는 원문 길이**: 변경 하나당 앞 500자만 보낸다. EU 법령은 본문 앞 40,000자를 기준으로 요약하며, 보고서에 그 사실을 적는다. 숫자 변경은 길이와 상관없이 따로 뽑아 보낸다.
- **연혁이 끊긴 고시**: 여러 부처 공동 고시 등은 검색 목록에 과거 버전이 안 잡힐 수 있다. 이 경우 첫 실행은 제·개정문만 요약하고, 다음 개정부터 조문을 비교한다.
- **법률·시행령**: 지금은 행정규칙(고시·지침)만 다룬다.
